# 设计原则（Design Principles）

> 当文档之间冲突、或遇到本手册未覆盖的取舍时，按本文排序裁决。

## A. 游戏设计四支柱（不可妥协）

### 1. 凡人感
主角是资质平庸的凡人。含义：
- 资源永远稀缺，机缘永远珍贵；不送白嫖的强力装备
- 突破可以失败但**绝不删档降境界**——挫败感来自"还要再攒"，不是"推倒重来"
- 敌人比主角强时，正确解法是逃跑、借势、等待时机——系统必须支持这些选项

### 2. 探索驱动
- 隐藏任务**不放感叹号**：发现感 > 引导效率
- 每张地图至少 1 个与主线无关的秘密（洞府/遗骨/奇遇 NPC）
- 随机遭遇表必须包含"纯氛围事件"（如路旁茶棚闲谈），世界才有生活气

### 3. 配置化内容
- 写死在代码里的数值/文案 = bug。一切进 `content/`
- 判断标准：策划（或 AI）不改一行 TS 就能新增一件装备、一条支线

### 4. 碎片可玩
- 玩家掏出手机的 3 分钟内必须能完成一个完整动作单元（一次战斗/一段对话/一次炼丹）
- 挂机修炼有收益但封顶——离线进度是甜点不是主菜

## B. 工程原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **Schema 即法律** | 先改 schema 再写数据，CI 校验不过不上线 | 手搓 JSON 字段名 |
| **移动端优先** | 所有 UI 先在小屏验证再管桌面；触控目标 ≥44px | 悬浮提示(hover)承载关键信息 |
| **存档容错** | 存写失败静默重试，永不因 IO 阻塞游戏循环 | await 存档卡渲染 |
| **负反馈温和** | 战斗失败→回城疗伤扣灵石；炼丹失败→废丹可售 | 死亡掉落已装备品 |
| **数值有锚点** | 一切伤害/消耗相对基准值推导，禁止拍脑袋魔数 | "这招感觉 999 挺帅" |
| **文本可替换** | 文案集中、无拼接字符串（为未来多语言留路） | `"你击杀了"+name+"！"` |

## C. 内容文风准则（摘要，全文见 GDD 附录 A）

- 古典白话 + 修仙术语；称谓体系：道友/前辈/道号
- 描述文本 ≤200 字，一段话内完成"是什么+来历/效果+一句韵味"
- 忌：现代词（秒杀除外作为玩家黑话）、日式和风词、网文爽文腔（"震惊！"）
- 示例对比：
  - ❌ "超强的神器！攻击力爆表！"
  - ✅ "黄枫谷外门制式法剑，剑身刻青云纹，注入灵力可放三尺青芒。"

## D. 手感与打磨（Game Feel）

> 打磨不是收尾装饰，而是核心循环的一部分。机制正确但无反馈的动作 = 未完成。
> 依据：业界共识"Juice it or lose it"——同样的机制，反馈层决定好玩与否。

- **反馈三件套**：每个新交互动作（攻击命中/拾取/突破/逃跑）必须同时具备：
  - 视觉：受击闪白 / 屏震 / 粒子或补间（至少其一）
  - 听觉：音效占位（M4 前允许程序化生成，不允许沉默）
  - 数值：伤害/收益浮动文字
- **反馈有上限**：打磨传达信息而非淹没玩家；同屏特效冲突时以可读性优先
- **手感参数一律常量化**：时长/幅度/缓动集中在使用模块顶部（如 `HITSTOP_MS`），为调参留路
- **真机试玩是完成标准的一部分**：每次玩法迭代后必须上手玩一次，并产出至少一条具体观察
  （❌"感觉不好" → ✅"逃跑后滑步太远，需要摩擦减速"）。用具体观察驱动下一轮修正，
  禁止凭"编译通过"宣布玩法特性完成

## E. AI 量产内容反模式（红线）

> 本项目由 AI 批量生产代码与内容。以下是从大量失败项目中总结的典型翻车模式，逐条对照：

| 反模式 | 表现 | 防线 |
|---|---|---|
| **广度换深度** | 一次提交铺 10 张地图、50 件物品，个个浅尝辄止 | 裁决流程 F.2：质优先；一个 PR 只深打一个系统 |
| **同质化内容** | 新物品/事件与已有内容仅换名字数值 | 新内容必须声明至少一处刻意差异（用途/时机/风险结构） |
| **清单式游戏** | 功能列表全勾但核心循环不成立 | 先验证垂直切片好玩，再横向扩内容 |
| **AI 代做设计决策** | 支柱冲突、数值锚点缺失时 AI 自行拍板 | 按裁决流程 F.3 停下问人，禁止静默取舍 |
| **编译通过 = 完成** | 类型检查绿了就算做完 | 完成定义见 CODING_GUIDELINES §9：校验+场景脚本+真机试玩 |
| **氛围空洞** | 世界有物件没生活气 | 探索驱动支柱：纯氛围事件、与主线无关的秘密是硬指标 |

## F. 裁决流程

1. 玩家体验 vs 开发便利 → 体验优先，但记录技术债到 PROGRESS.md
2. 内容量 vs 内容质 → 质优先（10 条好支线 > 50 条流水账）
3. 本文档 vs GDD → GDD 管游戏内容设计，本文管价值观与取舍，冲突时停下讨论
