## 3. 工作树纪律（沿用并强化）

1. 每个功能/内容批次一个 worktree 分支（`design-v2` 为例），绝不在 main 直接改
2. 分支命名：`feat-*`、`fix-*`、`content-*`、`docs-*`，短而描述
3. 集成：冲突解决后跑满 G1–G4（线上 G5 在合并后跑），再快进 main 发布
4. 合并完由**玩家/用户决定是否保留 worktree**；不擅自删

## 5. 大方向：V1 垂直切片走通"一小时沙盒"

> 核心方法论：**先让玩家在一张图一小时里玩出悬念**，再横向铺世界。

### 5.1 范围锁定（V1 就这三张牌）

```
一张图：杂役院（新作，教采集/炼丹/交易/逃命）
三个人：墨大夫（恩师，日程：药园↔诊堂）、杂役头张二（记恨池）、
        坊市散修李三（打探消息/换干货）
一个闭环：采集 3 时辰 → 炼丹 → 坊市换灵石 → 打坐/突破（寿元推进）→ 触发事件"杂役院失窃"
```

### 5.2 V1 任务拆解（建议 PR 顺序）

| PR | 内容 | 验收 | 依赖 |
|---|---|---|---|
| V1.1 | 时间轴核心：时辰→日→季节，HUD 时钟，消耗规则 | 移动/炼丹推进时辰，存档恢复保真 | V0 |
| V1.2 | 杂役院地图 + 采集点（灵草/矿石 3 类，消耗时辰） | 采集动效+刷新周期 | V1.1 |
| V1.3 | 3 NPC 日程化（跑到自己点位）+ 关系图雏形（好感/记恨） | 张二在"辰时"能看到玩家在药园偷摘→记恨+1 | V1.2 |
| V1.4 | 事件风暴首例："杂役院失窃"（条件：玩家长期旷工+张二记恨>2） | 结果为"张二告发→扣灵石+坊市风评下降" | V1.3 |
| V1.5 | 寿元推进（境界→寿元），HUD 倒计时，"续命"首次抉择 | 突破失败显示"寿元剩余 37 年无望筑基" | V1.1 |
| V1.6 | 涌现回归框架 `scripts/sandbox-sim.ts`（首个版本） | 模拟 ≥5 种玩家行为×30 日无异常 | 全部之上 |

### 5.3 V1 完成的"证据"（必须真实跑出）

1. G1–G4 全绿（validate/build/check:combat/check:quest/qa-local）
2. sandbox-sim 产出一张表：5 种策略（啃老/挖药/抢人/炼丹/内卷）→ 各自 30 日结局不同
3. 真机 or preview 玩 10 分钟，至少一条具体观察入库（如"凌晨去药园偷药时张二还没醒，没发现"）

## 6. 涌现系统 V2：自由度与因果关系

### 6.1 关系图 → 恩仇系统

- schema：`npcs[].relations = { npcId: { affinity, type: mentor|rival|debt|spouse|enemy } }`
- 行为写回：偷/抢/救/送礼 → affinity ±；累积到阈值 → 进入事件风暴（报恩/寻仇）
- 边界：**关键剧情 NPC 免疫死亡**（防断链），但普通 NPC 可死于兽潮

### 6.2 NPC 日程大泛化

- 位置 = 日程表查表（可被"打探"得到）；移动用已有寻路/传送
- NPC 也能"修炼"——随时间升级，到寿元大限陨落（世界层面的生命周期）

### 6.3 危险度带落地

- 删 portal 章节锁 → 全图可达；越界靠"信息差+伤害"软拦
- 进入危险区战斗失败 → 重伤回安全区（温和惩罚，寿元照走）

## 7. 内容量产 V3：质优先于量（AI 反模式红线照搬）

> DESIGN_PRINCIPLES §E 六条反模式是本阶段执法标准：广度换深度 / 同质化 / 清单式 / AI 代做决策 / 编译=完成 / 氛围空洞。任何一条踩线即打回。

### 7.1 内容生产流水线（每一条必须走完全流程）

```
1 策划意图（一句玩家体验） → 2 schema 先行 → 3 数据 JSON（含"刻意差异"声明）
→ 4 npm run validate → 5 场景脚本/涌现测试覆盖 → 6 真机走查 → 7 入库 TRACKER
```

### 7.2 主线重制 = 剧本事件（示例）

旧：`qm_01 前置满足→接取→收集→交付`（珠子）
新：`血色试炼塔开启（每 2 月一轮，坊市传闻 7 日内 rng 显现）→ 玩家可进 → 塔内限时淘物 → 秘境关闭`
效果：主线成为"舞台"，玩家选择"何时在台上"。

### 7.3 支线 = 欲望池变体

- 支线存"欲望池"（NPC desires），不写死接取时机
- 同一需求可有 2–3 种解法（灵石/人情/灵石+偷），因果不同

## 8. 公测打磨 V4

- **展现补齐**（一期缺口）：突破仪式全屏动画/顿悟天象/心魔情节
- **数值平衡**：以 GDD §2/§3 数值为锚（炼气一层裸装凡剑=攻10），用 combat-check 锚点用例回归
- **新手软引导**：杂役七日打样 + 面板渐进解锁 + first-time toast（入存档）+ 可跳过
- **全机型真机**：360/393/414/430 × ≥2 高度各测一遍 HUD 与战斗面板出界
- **pack:itch**：沿用 `npm run pack:itch` 出 WWW 包

---

## 9. 运营迭代 V5（发布后）

- 周期：**周更小版本**（平衡/事件模板/支线），月更大版本（新区域/系统）
- 反馈闭环：issue/评测 → 归类（崩溃>软锁>数值>内容）→ 修复 PR 跑满门禁 → 下个发布窗口
- 冷却：任何物理实体变化（波及数值/地图）必须跑 sandbox-sim 回归，防世界状态爆炸

## 10. 测试与质量门禁（G1–G6 全貌）

| 门禁 | 命令 | 覆盖 | 2.0 增补 |
|---|---|---|---|
| G1 | `npm run validate` | 内容 schema + 跨引用 | region/event/npc-schedule schema 纳入 |
| G2 | `npm run build`（先删 tsconfig.tsbuildinfo） | 类型+构建 | 世界快照类型保真 |
| G3 | `npm run check:combat` / `check:quest` | 战斗/任务纯函数 | 新增采集/炼丹火候/寿元用例 |
| G3b | `node scripts/sandbox-sim.mjs` | **涌现回归（新）** | 模拟 N 日：死锁/资源爆炸/坏档/断链 |
| G4 | `node scripts/qa-local.mjs` | 本地 E2E | 时间推进/日程移动/事件触发场景 |
| G5 | `node scripts/qa-live.mjs` | 线上冒烟 | 部署后快照恢复正确 |
| G6 | push main → CI 部署 | 发布管道 | 校验失败禁部署（照旧） |

**规则**：G3b 不绿不进 V3 以后任何发布；夜间 sandbox-sim 纳入 CI 可选（夜间 cron）防回归。

## 12. 风险清单与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 沙盒模拟吞噬开发时间（模拟器过重） | 中 | V1 只模拟"玩家周边 1 图"; scope 新增功能必须跑通再泛化 |
| AI 量产同质化事件 | 高 | "刻意差异"声明 + 涌现测试强制项 |
| 关系图导致剧情断链 | 高 | 关键 NPC 不死保护 + 事件链 integrity 校验入 G1 |
| 寿元惩罚劝退手机玩家 | 中 | 保持"不删档"，寿元用尽重伤有救（二期续命），上线 A/B 观察流失 |
| 世界快照过大 | 中 | 快照按区域懒加载、玩家码/世界码分离（二期） |
| 主线程卡（NPC 日程/事件轮询） | 中 | 模拟 tick 频率按场景段降采样，性能预算沿用 QA-5 |
